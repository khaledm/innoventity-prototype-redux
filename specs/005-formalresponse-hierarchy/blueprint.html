SubmitManufacturingResponse.cs — Guard Chain (T021)
public static async Task<IResult> Handle(
    Guid innovationId,
    SubmitManufacturingRequest req,
    AppDbContext db,
    ClaimsPrincipal user)
{
    // 1. JWT → actorId
    var actorId = user.GetActorId();

    // 2. Actor type guard
    var actor = await db.Actors
        .FindAsync(actorId);
    if (actor.ActorType != ActorType.Manufacturing)
        return Results.Forbid();

    // 3. Innovation existence + Published guard
    var innovation = await db.Innovations
        .Include(i => i.FormalResponses)
        .FirstOrDefaultAsync(i => i.Id == innovationId);
    if (innovation is null ||
        innovation.Status != InnovationStatus.Published)
        return Results.NotFound();

    // 4. Ownership conflict
    if (innovation.ActorId == actorId)
        return Results.Conflict("Owner cannot bid.");

    // 5. Duplicate response
    if (innovation.FormalResponses
        .Any(r => r.ActorId == actorId))
        return Results.Conflict("Already submitted.");

    // 6. Year contiguity + max 10
    var years = req.YearlyManufacturingCosts
        .Select(c => c.Year).OrderBy(y => y).ToList();
    if (years[0] != 1 ||
        years[^1] != years.Count ||
        years[^1] > 10)
        return Results.UnprocessableEntity(
            "Years must be contiguous 1-N, max 10.");

    // 7. Rationale length validation
    var rErr = ValidateRationale(req.YearlyManufacturingCosts);
    if (rErr is not null)
        return Results.UnprocessableEntity(rErr);

    // 8. Persist
    var response = new ManufacturingResponse { ... };
    db.FormalResponses.Add(response);
    await db.SaveChangesAsync();
    return Results.Created($"/bids/{response.Id}",
        new { response.Id, response.ResponseType, ... });
}

Year Contiguity + Rationale Validator — shared helper (T021/T025/T029)
private static string? ValidateYearlyProjections<T>(
    IList<T> items,
    Func<T, int> getYear,
    Func<T, IEnumerable<(string fieldName, string? value)>> getRationales)
{
    if (!items.Any())
        return "Projection list must not be empty.";

    var years = items.Select(getYear).OrderBy(y => y).ToList();
    for (var i = 0; i < years.Count; i++)
        if (years[i] != i + 1)
            return $"Years must start at 1 and be contiguous. " +
                   $"Found gap at index {i} (year {years[i]}).";

    if (years[^1] > 10)
        return $"Maximum projection year is 10. Got {years[^1]}.";

    foreach (var item in items)
        foreach (var (field, value) in getRationales(item))
            if ((value?.Length ?? 0) < 20)
                return $"Field '{field}' rationale must be at least 20 characters.";

    return null; // valid
}

Resolved Clarifications — Session 2026-06-07

All five questions from the /speckit-clarify session. Each answer is now reflected in spec.md, contracts/api-contracts.md, and data-model.md.

Should participationProposal be visible to non-owner actors in GET /bids?
Option C — Visible only to the submitting actor (for their own response) and the innovation owner. All other actors receive only public summary fields. This established the 3-tier visibility model (Tier 1: owner / Tier 2: submitter / Tier 3: other) now formalized in FR-013 and the API contract.
Should InvestorResponse.Feedback follow the same 3-tier visibility rule as participationProposal?
Option A — Yes. Feedback is visible to the submitting investor and the innovation owner only. Third-party actors do not see the Feedback field in the GET /bids response. Consistent with the Tier 2 rule that submitters see their own full data.
When a submitting actor calls GET /bids, should they see their own financial projections and rationale — not just participationProposal?
Option A — Yes. Submitting actors see their full own response including projections and rationale. Only other actors' responses are redacted to public summary fields. This simplifies implementation: "return full DTO for own response, return summary DTO for all others."
Is participationProposal (≥100 chars) required for InvestorResponse even though it already has a dedicated feedback field?
Option A — Yes, required for all four response types. The proposal and feedback serve distinct purposes: participationProposal is a structured statement of intent (investment terms, equity structure) while feedback is the investor's qualitative analysis of the innovation. Both are mandatory for InvestorResponse.
What is the maximum character limit for InvestorResponse.Feedback?
2000 characters. Matches the DB column allocation nvarchar(2000) and is appropriate for written investment analysis. Reflected in data-model.md (| Feedback | nvarchar(2000) | NULL (min 50 chars, max 2000 chars) |) and the API contract POST /bids/investor request body.
